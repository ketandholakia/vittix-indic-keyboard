## Unreleased

- Housekeeping batch: the README's shipped-layout inventory now lists all 21 layout files (generated from `layouts/**/*.json`, with script and encoding columns) and describes the `press_custom_1` blank template; layout_ids are normalized to the underscore-only style (`shree-dev-0708` → `shree_dev_0708`, `krutidev-010` → `krutidev_010`, `gujarati-remington[-unicode]` → underscored) with `SetActiveLayoutByID` comparing canonicalized IDs so hyphenated IDs saved by older builds keep working (the normalization IS the alias map); the validator warns about hyphenated IDs and about layouts with no mappings at all, and the tray menu hides mapping-less layouts (they type nothing); `reviews.txt`, `diff-stat.txt`, `.openclaw-attachments/` and `TOOLS.md` are removed from the repository and gitignored; the installer reads `AppVersion` from the built exe's version resource (single version source), declares `PrivilegesRequired=admin` explicitly and refuses to run while the app holds its `AppMutex` (matching the per-session `Local\` mutex); `verify.ps1` gained an optional env-var-gated signtool step and `docs/RELEASE.md` documents the signing, installer, and release flow; a new interactive hooks integration test lives in `Tests/manual/HookOrderTest` (real LL hook + real engine + scripted real key events, README documents build/run/scenarios).

- Key-up symmetry: the hook now consumes the key-up of any key-down it consumed (a bounded fixed-size consumed-VK set, cleared on the matching key-up and on foreground changes); key-ups of pass-through key-downs stay untouched. Some applications act on a key-up whose down never reached them — that ghost input is gone.
- `ProductionVKToUnicode` now passes `(Scan and $FF)` to `ToUnicodeEx` while keeping the full scan for `MapVirtualKeyEx`: in ToUnicodeEx's scan parameter bit 15 means "key released", and the `$E0` extended-key prefix sits in the high byte, so every extended key (arrows, numpad `/`, numpad Enter) converted as if it were a key-up and yielded no text. The numpad slash now converts to `/` again.
- Removed the never-implemented action hotkey: the `MessageBox` TODO handler in `WMHotKey`, its registration, the Settings dialog field, and the `ActionHotkeyText` setting. A stored `[Hotkey] Action` key in an older settings.ini is ignored and kept on disk (backward compatible).
- Neutral first-run defaults: `TargetProcessName` and `AllowedProcesses` default to empty (fail-closed — nothing is intercepted until the user adds apps) instead of shipping a hardcoded `CorelDRW.exe`. Existing users' saved values are untouched. The first-run notice now explains how to add apps (tray "Allowed apps" menu or Settings).
- UWP apps are now resolved to the real app: when the foreground process is `ApplicationFrameHost.exe`, the hook resolves the process name through the first child window owned by a different PID (`EnumChildWindows`), cached by frame HWND/PID as before; failure keeps the host name (fail-open).

- Mouse clicks into another field (or another caret position in the same field) now cancel the engine's pending prebase/reph and the emitted-length stack: a new `WH_MOUSE_LL` hook, installed and removed together with the keyboard hook (and restarted with it), calls the engine-owned `ResetPendingOnPassThrough` on left/right/middle button-down, so a stale matra can never be committed at the clicked position even when the foreground window does not change (the foreground sink never fires on an in-window caret move). The callback is allocation-free, never consumes mouse input, and deliberately does NOT re-arm the injection latch — only a foreground change does. Mouse moves and button-ups leave the typing flow intact.

- Shipped layout fixes now reach existing users: the per-user seeded layouts copy carries a `.seed.json` manifest (per-file SHA-256 of the shipped version when copied, plus the app version), and a startup reconcile pass copies missing shipped layouts, overwrites unmodified copies with newer shipped versions (after an `EnsureBackup`), leaves user-modified copies alone with a logged warning, and never touches user-created files. Existing installs are bootstrapped safely: manifest-less files whose content still matches the shipped version are adopted, everything else is treated as user-modified. The tray reports applied updates as a one-line startup balloon; `.seed.json` is excluded from layout loading (dotfiles are control data).

- The single-instance mutex is now `Local\VittixIndicKeyboardInstance` (per session) instead of `Global\...` (per machine): a second Windows session (Fast User Switching, RDP, another console user) can run its own instance again, since per-session low-level hooks and per-user settings/layouts are fully independent. The Layout Editor has no single-instance mutex (nothing to align); the installer gains a matching `AppMutex` entry with the housekeeping batch.

- Fixed Tab/Enter output ordering with a pending matra: when the engine commits a pending prebase/reph on Tab/Enter, the injected matra is queued after the physical control key that is still in flight, so it could appear in the field the Tab/Enter just moved to. The hook now consumes the physical key and re-injects it in order after the text (`SendVirtualKeyWithShift` keeps Shift around the re-injected key so Shift+Tab still moves focus backwards). With nothing pending (or a zero/partially accepted flush) the physical key still passes through natively — the hook only replaces a key it actually emitted text for. Manual real-hardware ordering checklist in `docs/MANUAL_VERIFICATION.md`.

- Documented the dedicated hook-thread design (`docs/hook-thread-design.md`, stage b of the hook-stability work): thread + message loop, the mutation-marshal table, the single engine critical section discipline, test impact, and the four-step rollout. Not implemented in this change — the watchdog (stage a) already removes the worst failure mode, and the design is written up instead of risking the full threading refactor in one step.

- The low-level keyboard hook now has a watchdog (stage a of the hook-stability work): the LL callback stamps a heartbeat tick on every event, and a 30 s timer in the tray compares it against `GetLastInputInfo` — input the hook never saw beyond a 120 s window means Windows silently removed the hook (its classic timeout behavior), and it is re-installed, with each re-install logged. Session unlock (`WM_WTSSESSION_CHANGE`) and resume from sleep (`WM_POWERBROADCAST`) restart the hook unconditionally via `WTSRegisterSessionNotification`. The re-install is guarded to hooks this process owned, so hook-less hosts (tests) are never touched.

- The SendInput-failure latch is now per foreground window: a `HandleForegroundChanged` re-arm means a UIPI block against one elevated app no longer silently stops translation in every other app (previously the latch stayed down until a manual toggle, layout switch, or settings apply). A new `SetInjectionStatusCallback` seam (nil by default, fires on state transitions only) lets the tray announce the latch trip exactly once with a "Typing is blocked in this app, probably because it is running as administrator. Keys pass through unchanged." balloon, show an alternate blocked icon state (the greyed frame plus a matching hint while the engine stays enabled), and clear both when the latch re-arms.

- Layout Editor backup copies (`<layoutdir>\_backup\<name>_<timestamp>.json`) are no longer loaded as layouts: `TLayoutManager.Initialize` skips every file inside a `_backup` folder (case-insensitive), so a stale backup carrying a duplicate `layout_id` can no longer win the sorted-order race against the real file, and the shared seeding copy in `LayoutsPathResolver` now copies the shipped tree without `_backup` folders. The folder name is defined once (`BackupManager.BACKUP_SUBDIR_NAME`).

- Layout Editor review fixes for the direct_classes column: pasting an old 2-value clipboard row over a mapping that carries a class no longer leaves the stale class attached to the pasted key (the clipboard is the row's whole content; the Class cell clears), paste/Add Key mirror the glyph into the Preview column, the designer DFM declares the real 4-column grid, a class entry whose key loses its glyph is pruned on save instead of surviving as an invisible orphan, and the validator warns about unknown class values (anything outside `consonant`/`vowel`/`other` — the engine silently treats them as `other`, changing cluster behavior). A present-but-empty `inherent_vowel_key` now reports exactly one diagnostic instead of two.
- In the Layout Editor, the Direct tab now exposes a "Class" column (Key, Glyph, Class, Preview) showing the key's `direct_classes` classification (`consonant`, `vowel`, `other`). Cell edits in the Class column round-trip through `SyncUIToModel`/`SyncVisibleStringMap` with search filter preservation and clipboard copy/paste support.
- Tightened layout validation: cross-checks the value of `inherent_vowel_key` (verifies non-empty, existence in DirectMap, and `vowel` classification in direct_classes) and warns on duplicate `move_to_cluster_start` modifier rules. Pinned cluster-clear semantics for legacy layouts (consonant + standalone vowel + vowel in Kruti Dev produces standalone vowels instead of attaching matra).

- Completed the remington metadata fix: `font_family` is now `Nirmala UI` to match its Unicode glyphs (the label became `unicode` in the A.5 fix, but the legacy `Gopika` name made the editor/OSK glyph view render Unicode code points in a legacy font).
- The Settings dialog now exposes the layouts folder: an editable path with a Browse button and an OK-time empty check. Apply flows through the existing resolution (a missing/unwritable folder falls back to the per-user layouts copy and persists the resolution).
- New optional "Cycle layout hotkey": a configurable global hotkey (unbound by default) switches to the next loaded layout, wrapping at the end, through the same switch path as the tray menu (engine re-attach, default-layout persistence, header/menu/OSK refresh) and names the new layout in a tray balloon. Persisted as `[Hotkey] Cycle`.
- Phonetic layouts now type like a phonetic IME instead of emitting glyph strings verbatim (opt-in, data-driven):
  - **Auto-halant:** in a `layout_type: "phonetic"` layout whose halant modifier declares `"behavior": "join_next"`, a consonant key pressed while a consonant cluster is open emits the halant glyph + the new consonant as one atomic half-form (`kk` → ક્ક, `kks` → ક્ક્સ), one backspace unit per half-form. Legacy layouts keep verbatim output regardless of their tags.
  - **Inherent-vowel suppression:** a phonetic layout declaring `properties: {"inherent_vowel_key": "a"}` absorbs that vowel-classified key right after a consonant (`ka` → ક), and the absorption ends the cluster so `kak` gives two full consonants. Strict opt-in; the capital variant and all other vowels are standalone. Accepted limitation: after a matra the cluster is closed, so `kwa` gives કાઅ (matras have their own keys in these layouts).
  - **Reph by metadata:** the engine resolves the reph rule by `"behavior": "move_to_cluster_start"` instead of the hardcoded rule name, with a rule-name fallback for untagged layouts; pending/flush mechanics unchanged.
- Both phonetic layouts (`gujarati_phonetic`, `hindi_phonetic`) now carry `direct_classes` (generated mechanically from the glyph codepoints: consonants, independent vowels, matra signs as `other`), the `join_next` halant tag, and the `inherent_vowel_key` property. The validator retires the blanket "engine has no phonetic support" warning and now warns only about the opt-ins a phonetic layout is missing; a `move_to_cluster_start`-tagged modifier rule is no longer reported as unexecuted metadata.
- The on-screen keyboard is now clickable-to-type: clicking a key feeds the mapped character through the same engine path as a physical keystroke (cluster context, prebase/postbase, reph, halant all apply). The keyboard window no longer takes focus on click (`MA_NOACTIVATE` + new `TVittixKeyboardView.FocusOnClick` property), so the typed glyph lands in the window you were working in; clicks are no-ops when typing is disabled or no layout is active. Space/Backspace/Enter are still special keys that do not fire the select event. New `OSKInput.OSKKeyNameToEngineKey` maps the view's uppercase letter names (plus shift state) to the engine's case-sensitive keys.
- New "Ignore injected keystrokes (recommended)" checkbox in Settings, persisted as `IgnoreInjectedInput` in `[General]` of settings.ini and applied through `SetIgnoreInjectedInput` at startup and on every settings change. Default on, preserving the hook's historical behavior; uncheck only for remote desktop or macro tools whose keystrokes must drive the mapping.
- `layouts/gujarati/remington.json` now declares `encoding: "unicode"` — after the mojibake repair all its glyphs are real Gujarati code points, and a legacy label made the editor/OSK render them through the legacy Gopika font. A new data-integrity gate (`ScriptBlockGlyphLayout_MustDeclareUnicode`) ties the label to the data: script-block-Unicode layouts must say "unicode"; the KrutiDev family keeps "legacy" because its decoded modifier glyphs (`µ`, `©`, `Æ`, `Ÿ`) are legacy font codes.
- Removed the dead `frmSequenceEditor` dialog (unreachable since the sequences runtime removal; only the dpr/dproj registration kept it alive).
- Repaired the cp437 mojibake in the shipped legacy layouts: 54 glyph values across `gujarati/remington.json` (all 44 of its glyph values) and the Devanagari `krutidev_010` / `shree_dev_1076` / `shreelipi_0708` (anusvara → `µ`, visarga → `Ÿ`, reph → `©`, Shree-Dev i-matra → `Æ`) were UTF-8 bytes mis-read through cp437 when the files were authored; the stored strings are now the originally authored glyphs (decode recipe `stored.encode('cp437').decode('utf-8')`, full key→glyph table in the fix(A.1) commit). remington now types real Unicode Gujarati: `k` → ક, `kA` → કા. A data-integrity gate test (ASCII / Latin-1 / Latin Extended-A / Devanagari / Gujarati only) keeps cp437 remnants out of all four files. The pure-ASCII legacy font-key mappings in the Devanagari layouts are untouched, and remington's `encoding: "legacy"` label is unchanged (relabeling is a separate sign-off decision).
- Completed `direct_classes` for the KrutiDev-family layouts: `m` (types `;`, which is म per the documented Kruti Dev 010 chart) is classified `consonant` in krutidev_010 and shreelipi_0708. `q` and `Q` stay deliberately unlisted — the chart sources are ambiguous about what the font strings `Q`/`qq` render as without the real font, and unlisted keys keep the legacy behavior.
- Layout schema versioned at 1.1: `CURRENT_LAYOUT_SCHEMA_VERSION` bumped, the validator accepts declared `1.0` and `1.1` and still rejects any other declared version, an absent version field still defaults to the current version, and the four direct_classes layouts now declare `"version": "1.1"` while the other six layouts stay exactly as they are.
- The editor now backs up layout files before overwriting them: every save site (Save, Save As, Export) calls `EnsureBackup(fileName, DefaultBackupOptions)` first, so an existing target gets a `_backup/<name>_<timestamp>.json` copy (max 20 kept, oldest rotated out) before the overwrite. Brand-new files are never backed up. Always-on for now — `LayoutEditorSettings` has no backup preference yet.
- Backspace length now survives word boundaries: a printable key that passes through natively (Space, digits) records its UTF-16 unit length on the emitted-length stack instead of clearing it, so backspacing into the previous word's multi-unit legacy glyph (`vks`, 3 units) deletes the whole glyph again. The stack is capped at 256 entries (oldest dropped) and is still cleared by caret/field-changing events (Esc, Ctrl/Alt/Win shortcuts, arrows/Home/End/Delete, foreground change, Tab/Enter, layout switch, engine disable, injection failure). New engine `ResetClusterContext` documents the split.
- Positional key mapping by scan code: the production conversion re-derives the virtual key from the hardware scan code through the fixed US layout (`MapVirtualKeyEx` with `MAPVK_VSC_TO_VK_EX`, extended keys carrying the `$E0` prefix, unmappable scans falling back to the incoming VK), so positional layouts (InScript, Remington) stay aligned on non-US physical keyboards. Injected as `THookPolicyDependencies.ScanToVK`.
- The fixed US layout handle is preloaded once in `InstallKeyboardHook` (before `SetWindowsHookEx`), so the first keystroke no longer pays `LoadKeyboardLayout` inside the low-level hook callback; the lazy fallback remains as a safety net.
- Consonant-only cluster context: layouts can add an optional top-level `direct_classes` section (`consonant` / `vowel` / `other`); the engine opens its contextual-matra cluster only for consonant-class direct outputs, so a consonant followed by a standalone vowel can finally be typed in legacy layouts. Shipped for krutidev_010, shreelipi_0708, shree_dev_1076 and gujarati/remington (classification in commit b5d777a for review). Layouts without the section behave exactly as before; the validator warns about stale entries and the editor round-trip preserves the section.
- Failed settings-apply and layout reloads now re-attach the engine: the detach/reload/re-attach decision moved into the non-visual `Keyboard/Layout/LayoutReload.pas` helper, which restores the previously active layout ID and re-attaches the engine before re-raising, so typing keeps working and the error is reported exactly once.
- The editor's Keyboard tab and the on-screen keyboard now draw the mapped glyph in the layout's own `font_family`, the same font the Preview column and the typing preview already use. Legacy layouts store ASCII code points (Kruti Dev 010 maps `k` -> `d`), so those keys previously showed Latin letters where the Preview column showed the Indic glyph. The physical key label stays in the control font, because a legacy ASCII-mapped Indic font would draw the label as an unrelated glyph. New `TVittixKeyboardView.GlyphFontName` property carries this; empty means "use Font".
- Fixed the editor's Keyboard tab not repainting after an inspector edit was applied: `SyncUIToModel` writes the mapping into the model but nothing invalidated `vkvKeyboard`, which paints on demand only, so the key kept showing its previous glyph until an unrelated repaint (clicking another key, switching tabs) happened to run. Every model write now ends in `RefreshKeyboardView`.
- Fixed the inspector's Clear button doing nothing from the Keyboard tab: it required focus to already be on a grid, so it exited before clearing. It now resolves the target the same way Apply does (focused grid, else Direct, located by the inspector's key).
- Removed the dead multi-key `sequences` runtime path. It never fired (DirectMap resolved and cleared the buffer before a sequence could accumulate) and fundamentally conflicted with the reph mechanism (both key off `R`), so a documented sequence like `kS` silently produced two glyphs instead of the conjunct. Conjunct input now flows exclusively through the DirectMap/reph/halant path. `MAX_SEQUENCE_KEY_LEN` is retained so the editor/validator still reject overlong sequence keys.
- Fixed keystroke loss on the fallback path: a pending pre-base matra or reph that the hook had already consumed is now flushed before the engine sends the literal key (and before postbase/halant commits), instead of being silently discarded by `ResetEngineState`.
- Fixed modifier lag in `IsModifierComboActive` by reading physical state via `GetAsyncKeyState` (the same fix previously applied to `VKToChar`), so Ctrl/Alt/Win app shortcuts are no longer intermittently eaten by the hook under fast typing.
- Wrapped the low-level keyboard hook callback in a try/except so an exception cannot return an uninitialized `LRESULT` to Windows (which previously risked doubled or eaten keystrokes).
- Added injection-status tracking to `SendInput`: when a `SendInput` call reports 0 (e.g. UIPI blocks a target at a higher integrity level), the hook fails open and passes keys through instead of silently eating them; the status resets on engine toggle or layout change so interception recovers once injection succeeds again.
- Fixed stale engine key buffers, shared the sequence-length limit with the editor, and hardened layout JSON parsing so malformed input fails cleanly.
- Changed the app whitelist to fail closed when empty, so an empty whitelist no longer allows every foreground app; added warnings in the settings and tray UI before saving an empty allowed-process list.
- Added editor validation for overlong sequence keys so layouts cannot define sequences the runtime engine will never match.
- Restored batched `SendInput` behavior for multi-character Unicode output so grapheme clusters stay atomic again.
- Moved the `FromJSON` nil-check into the inner protected block so malformed layout JSON and field-population failures both free the partially constructed layout instead of leaking it.
- Let Ctrl/Alt/Win shortcuts pass through the hook, and remapped Tab/Enter to native virtual-key sends while still resetting engine state.
- Removed dead translator code, routed typing through the shared SendInput helper, and added basic logging around hook and layout initialization.
- Tightened small robustness issues in engine state initialization and backup naming so repeated runs do not overwrite recent backups.
- Manual repro for the key-buffer bug: type a direct consonant such as `k`, then type a sequence starter/prefix that previously left residue in `KeyBuffer`, and then type the matching conjunct trigger. Before the fix, the stale buffer could combine into the wrong sequence; after the fix, the direct mapping clears the buffer and the expected glyph path is preserved.
- Fixed Shift-lag in `VKToChar`: `GetKeyboardState()` called inside the `WH_KEYBOARD_LL` callback reads a global table that Windows has not yet updated for the current keystroke, so modifier state (Shift) can lag one keystroke behind on fast typing, producing wrong-case/wrong-glyph output. `VKToChar()` now builds a `TKeyboardState` manually from `GetAsyncKeyState()` for VK_SHIFT/VK_LSHIFT/VK_RSHIFT/VK_CONTROL/VK_LCONTROL/VK_RCONTROL/VK_MENU/VK_LMENU/VK_RMENU and `GetKeyState()` for VK_CAPITAL (toggle bit), eliminating the race. Regress: type a shifted character rapidly (e.g. Shift+K producing "K" then a shifted vowel) and verify the case/glyph matches the intended output, not the prior keystroke's modifier state.
- Hardened `LayoutFromJson` to raise a clear "Duplicate key in layout JSON" error before allocating `TKeyMapping.Metadata` when a duplicate key is detected in `prebase` or `modifiers`, preventing an orphaned dictionary leak that occurred when `TDictionary.Add` raised `EListError` on a duplicate key.
- Changed `ParseHotkey` to return `Boolean` indicating parse failure instead of silently falling back to `VirtualKey := Ord('K')`; callers in the tray now surface an "Invalid hotkey configuration" message box for malformed hotkey text.
- Removed `Keyboard/Core/KeyTranslator.pas` (dead code: `SetTranslatorHandler`/`TranslateKey` referenced nowhere) and its `DCCReference` entry from `Keyboard/VittixIndicKeyboard.dproj`.
